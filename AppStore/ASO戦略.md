# サブメモ ASO 戦略

作成日: 2026-08-10
対象: iOS「サブメモ / Submemo」（未リリース・iPhone 専用・iOS 26.0 以降）／日本 App Store・U.S. App Store

`ポモドーロ_ASO戦略.md` の枠組みを本アプリに当てはめたもの。
掲載する実際の文言は `AppStore/ストア掲載情報.md` にあり、本書はその**根拠**を書く。

---

## 0. エグゼクティブサマリー

本アプリは**未リリース**なので、ポモドーロのような「既存リスティングの立て直し」ではなく、
**最初から正しい形で出す**のが仕事になる。逆に言えば、名前を後から変えて順位をリセットする
リスクを負わずに済む唯一のタイミングでもある。

押さえるべきは次の3点。

**第一に、名前の30文字を使い切ること。** App Store で検索順位に最も強く効くのが名前で、
説明文は**検索インデックスに入らない**。初版で控えめな名前を付けると、その後どれだけ
説明文を磨いても検索には効かない。

**第二に、「サブスク管理」という激戦区での立ち位置を決めること。** この語は競合が名前に
入れて真正面から取りに行っている。同じ土俵に乗りつつ、本アプリだけが言える
**「銀行・カードに繋がない」**を差別化軸に据える。これは機能ではなく**不安の解消**で、
競合の多くが連携を売りにしているぶん、そのまま空きポジションになっている。

**第三に、レビューをゼロから積む導線が現時点で無いこと。** `SKStoreReviewController` は
未実装（確認済み）。新規アプリはレビュー数がそのまま信頼と順位に効くので、
**リリース前に実装しておく**のが最も費用対効果が高い。

**最優先の3アクション**は、(1) 名前・サブタイトル・キーワードの3層を重複なしで埋める、
(2) 英語ロケールのキーワード枠を使って日本 App Store での被覆を実質2倍にする、
(3) 達成タイミングでのレビュー依頼を実装する、である。

## 1. App Store の検索順位の仕組み（前提）

Google Play と違い、**App Store は説明文（Description）を検索インデックスに使わない**。
検索に効くテキストは次の3つだけ。

- **アプリ名（30文字）** — 影響が最も大きい。1文字も無駄にできない
- **サブタイトル（30文字）** — 名前に次いで効く。名前と別の語を入れる
- **キーワードフィールド（100文字）** — 非公開。カンマ区切りで詰める

加えて、テキスト以外の指標が順位とコンバージョンを左右する。
**ダウンロード数・コンバージョン率・レビュー数と評価・レビューの新しさ・継続率・更新頻度**。

### 節約ルール（本書で繰り返し使う）

1. **同じ語を名前・サブタイトル・キーワードで重複させない。** 重複ぶんだけ被覆が減る
2. **キーワード欄はカンマ区切り・スペース無し。** `固定費,節約` と書けば「固定費」「節約」
   「固定費 節約」すべてに当たるが、スペースで区切ると連結語としてしか拾われにくい
3. **記号に文字を使わない。** 括弧・中黒・感嘆符は検索に効かない
4. **英語ロケールのキーワード欄も、日本 App Store で追加インデックスされる**（後述 §7-2）

## 3. 競合分析

> 順位・レビュー数などの実数は未調査。リリース前に App Store で「サブスク管理」を検索し、
> 上位10件の**名前・サブタイトル・カテゴリ・レビュー数**を控えて本節を更新すること。
> 憶測の数字は書かない。

企画書 §9 で挙がっている競合と、想定される戦い方は次のとおり。

**「サブスク管理（解約忘れ防止・見える化）」型** — 名前に検索語を直接並べる王道。
学ぶべきは、`サブスク管理` + `解約忘れ` + `見える化` を一つの名前に同居させている点。

**「固定費をお得に管理」型** — 「固定費」という、サブスクより広い上位概念の語を取りに行っている。
本アプリもキーワード欄で「固定費」を押さえる。

**サブリス／Costly／SubKeeper 型** — ブランド名のみで、カテゴリ語を名前に入れていない。
検索では不利だが、指名検索とデザインで戦う型。**本アプリはこの型を採らない**
（ブランド名「サブメモ」は認知ゼロなので、指名検索が存在しない）。

**多くの競合が「銀行・カード連携」を売りにしている。** これは機能としては強いが、
「連携したくない」層をまるごと取りこぼしている。本アプリはそこを名指しで取る。

### 導かれる立ち位置

> **「連携しない × 綺麗 × 集計が賢い」**（企画書 §0 のポジショニングそのまま）

名前とサブタイトルで `サブスク管理` `解約忘れ` という**土俵の語**を確保しつつ、
`銀行に繋がない` という**空きポジションの語**を必ずどこかに入れる。

## 5. アプリ名（30文字）

### 推奨（本命）— 30文字

```
サブメモ サブスク管理・解約忘れ防止・固定費と節約の見える化
```

- 取れる語：`サブメモ` `サブスク` `サブスク管理` `解約` `解約忘れ` `固定費` `節約` `見える化`
- 記号は中黒（・）のみ。**「 - 」を廃止して2文字を語に振り替えた**
- **30字ちょうど**。1文字も余らせない

### 代替A（トライアルを名前で取る）— 24文字

```
サブメモ サブスク管理・解約忘れ・無料トライアル
```

無料トライアルの解約忘れが最大の恐怖なので、そこを名前で取りに行く型。
ただし「固定費」「節約」という広い語を落とすことになる。

### 代替B（ブランド性重視）— 20文字

```
サブメモ - サブスク管理と解約忘れ防止
```

現在の掲載情報に書いてある案。読みやすいが、**10文字を使い残す**。
ブランド認知がゼロの新規アプリでは、この余白は高くつく。

### English（30 characters）

```
Submemo: Subscription Tracker
```

29 characters。`Submemo` `Subscription` `Subscription Tracker` `Tracker`。
U.S. では `subscription tracker` `subscription manager` が主要検索語なので、
名前で `Subscription Tracker` を押さえ、`manager` はキーワード欄に回す。

## 6. サブタイトル（30文字）

名前で使った語（サブスク・管理・解約・固定費・節約）は**使わない**。

### 推奨 — 25文字

```
更新日を通知。月額も年額も自動計算。銀行に繋がない
```

- 新規に取れる語：`更新日` `通知` `月額` `年額` `自動計算` `銀行`
- 機能（自動計算）と差別化軸（非連携）を1行に同居させる

### 代替A（安心を前に出す）— 20文字

```
更新日を通知。銀行やカードに繋がない安心
```

`更新日` `通知` `銀行` `カード` `安心` を獲得。読みやすいが 10 字を使い残す。

### 代替B（トライアル訴求）— 24文字

```
更新日と無料期間の終了を通知。銀行に繋がない安心
```

`無料トライアル` `終了` `通知` `更新日`。名前で代替A（トライアル）を採らなかった場合の受け皿。

### English（30 characters）

```
Renewal alerts, no bank link
```

28 characters。`Renewal` `alerts` `bank` を獲得し、差別化軸を明示。

## 7. キーワードフィールド（100文字）

カンマ区切り・スペース無し。名前とサブタイトルで使った語は入れない。

### 7-1. 日本語ロケール — 88文字

```
定期購入,サブスクリプション,家計,家計簿,支出,料金,課金,引き落とし,支払い,トライアル,無料期間,値上げ,見直し,無駄,契約,カード,為替,ドル,一覧,明細,リマインダー
```

名前・サブタイトルで使った `サブスク` `管理` `解約` `固定費` `節約` `見える化` `更新日` `通知`
`月額` `年額` `自動計算` `銀行` は**入れていない**（重複回避・スクリプトで確認済み）。

### 7-2. 英語ロケールのキーワード枠を追加活用【重要】

本アプリは日本語・英語の2言語対応。**日本の App Store は、日本語ロケールに加えて
英語ロケールのキーワードフィールドも追加でインデックスする。**
つまり英語ロケールを設定すれば、日本 App Store での被覆を**実質約2倍**にできる。
日本語では取りにくい英字検索（"subscription" など）も拾える。

```
recurring,billing,manager,expenses,budget,reminder,monthly,yearly,spending,cost,money,trial,cancel
```

98 characters。英語ロケールの名前・サブタイトルで使った
`Submemo` `Subscription` `Tracker` `Renewal` `alerts` `bank` は入れていない。
`subscription` は名前に入っているため、キーワード欄からは外して `trial` `cancel` に振り替えた。

> **実装メモ**：App Store Connect で「英語（U.S.）」のローカリゼーションを用意し、
> 名前・サブタイトル・キーワードを設定する。反映は審査通過後、検索インデックスに
> 乗るまで数日かかることがある。

## 8. カテゴリ戦略

| | 設定 | 理由 |
|---|---|---|
| プライマリ | **ファイナンス / Finance** | 「サブスク管理」の競合はここに集まる。同じ棚に並ぶことが重要 |
| セカンダリ | **仕事効率化 / Productivity** | 「固定費の管理」という作業寄りの需要を拾う |

家計簿（収入・レシート・税）は扱わないが、**ユーザーの検索意図は家計側にある**ため
ファイナンスが主で問題ない。副カテゴリは検索順位への直接効果は限定的だが、
カテゴリ内ランキングとおすすめ面での露出機会が増える。

## 9. 説明文（CRO）

**説明文は検索インデックスに使われない。** キーワードを詰め込む場所ではなく、
**見た人を DL に変える**場所と割り切る。

勝負は最初の3行（「もっと見る」で折り畳まれる前）。本アプリの構成は次の狙い。

| 位置 | 内容 | 狙い |
|---|---|---|
| 1行目 | 「サブスク、いくら払っているか言えますか。」 | 問いかけで自分事化させる |
| 2〜3行目 | 手で書き留めるだけ／銀行に繋がない | 手軽さと安心を同時に |
| 以降 | 機能を見出し付きで6ブロック | 便益を1つずつ |
| 末尾 | プライバシーの具体的な説明 | 不安の解消でクロージング |

実文言は `ストア掲載情報.md` §5。

**社会的証明**（「◯万人が利用」「レビュー4.8」など）は未リリースのため書けない。
リリース後、実績が出た時点でプロモーションテキスト（審査不要で差し替え可）に入れるのが早い。

## 10. スクリーンショット・プレビュー戦略

検索結果には**最初の1〜2枚しか表示されない**ので、1枚目で価値提案を言い切る。
制作済みの6枚（`AppStore/store/`）は次の設計になっている。

| # | 見出し | 狙い |
|---|---|---|
| 00 | サブメモ／契約中のサブスクを、1画面で。＋特徴3つ | 検索結果で見える1枚目。何のアプリか3秒で伝える |
| 01 | 毎月いくら払っているか／開いた瞬間に | 中心的な便益 |
| 02 | 何にいくら使っているか／カテゴリごとに | 集計という差別化 |
| 03 | 無料トライアルの終了を／見逃さない | 最大の恐怖の解消 |
| 04 | このサブスク／年間いくら？ | 行動（見直し）の後押し |
| 05 | サービス名を／入れるだけ | 入力が面倒という離脱理由を潰す |

各枚に**便益の見出し**を載せてある（機能名の羅列にしない）。企画書 §6 のとおり
実ロゴは使わず頭文字タイルで作成しており、審査 5.2 のリスクを避けている。

### 未実施（推奨）

- **アプリプレビュー動画**（15〜20秒）。登録 → 合計が出る → 通知が届く、の流れを見せる
- **カスタムプロダクトページ**。「トライアル解約忘れ」向けと「固定費の見直し」向けで
  1枚目の見出しを出し分ける

## 11. レビュー・評価の獲得【最優先・未実装】

新規アプリはレビュー0件から始まるので、**最初の数十件が付くまでの速度**がその後を決める。
`SKStoreReviewController` は**現時点で未実装**（`grep` で確認済み）。リリース前に入れる。

### 出すタイミング（ポジティブな瞬間に限る）

本アプリでの「成功体験の直後」は次のあたり。

- **解約シミュレーションで「年間◯円浮く」を見た直後** — 最も満足度が高い瞬間
- サブスクを3件以上登録し終えた直後（全体像が見えた瞬間）
- 通知から開いて、トライアルを解約できた後

逆に、**起動直後・登録画面の途中・エラー後には絶対に出さない**。

### 運用

- `SKStoreReviewController` の表示は Apple が年3回までに制御する。無闇に全員に出さず、
  **一定回数以上使ったユーザー**に絞ると高評価が集まりやすい
- **アプリ内に問い合わせ導線を用意**し、不満のあるユーザーが★1を書く前に
  直接連絡できるようにする（現在の問い合わせ先は `angocat215@gmail.com`。
  設定画面から開ける導線は未実装）

## 12. その他のランキング要因

**更新頻度** — Apple は活発にメンテされているアプリを評価する。
`検討事項.md` に積んである項目（オンボーディング完了フラグ、価格履歴の複数保持など）を
小刻みに出していけば、鮮度シグナルとレビュー獲得機会の両方が得られる。

**継続率** — サブスク管理は「登録したら終わり」で開かなくなりやすい。
更新前の通知が**再訪の理由**そのものなので、通知の質が直接リテンションに効く。
ここは実装済みで、かつ文面に金額と日付を入れてあるので開かれやすい。

**In-App Events** — 「今月のサブスク棚卸し」のようなイベントを設定でき、
検索・おすすめ面で追加露出を得られる。無料アプリでも設定可能。

**ローカリゼーション** — 英語ロケールの名前・サブタイトル・スクリーンショットは整備済み
（`AppStore/store/en`）。§7-2 の英語キーワード枠と併せて有効化する。
